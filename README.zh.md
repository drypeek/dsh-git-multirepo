# dsh-git-multirepo

**在对话头部把 DSH 工作区内所有 git 仓库的历史合成一个列表来查看。**

[English](README.md) | 简体中文

> 面向 DeepSeek Harness 的非官方第三方插件，与 DeepSeek 无隶属关系，也未获其背书。

---

工作区里并列着多个 git 仓库时，逐个查看既慢又容易遗漏。这个插件会自动找出工作区内的全部仓库，把它们的提交放在一起展示，一眼就能回答「最近改了什么、哪些仓库落后了」。

## 你能得到什么

- **整个工作区一条时间线。** 所有仓库的提交按时间倒序排列，每行标明所属仓库。
- **远程与本地清晰分区。** 只存在于远程、尚未合并到本地的提交单独成组并可折叠，不会淹没在其他提交里。
- **按需展开详情。** 点击提交查看说明、作者、时间、哈希与变更文件；点击文件名在右侧栏打开差异。
- **一次拉取全部仓库。** 一个按钮更新所有仓库，并告知哪些失败；每个仓库还会显示领先/落后远程的数量。
- **不打扰的筛选。** 可隐藏不需要的仓库、按时间范围过滤，或搜索提交信息、作者与哈希。
- **滚动时保持位置。** 工具栏固定在顶部，并提供一键回到顶部与回到当前位置。

## 安装

需要 DSH 0.2.1-rc.5 或更新版本（差异视图使用了右侧栏的页签服务），以及 git 2.24 或更新版本（`--end-of-options`）。

把本目录作为插件 bundle 安装：

1. 在 DSH 中打开**设置 → 插件**，从本地目录安装 bundle 并选择本仓库目录。（也可以在 agent 会话里用 `plugin_manager` 工具：`install_bundle`，target 填本目录的绝对路径。）
2. 启用该 bundle。命令行等价写法是先执行 `dsh plugin --profile <profile> add link:/path/to/dsh-git-multirepo` 安装包，再到插件页启用 bundle。

然后刷新 Web GUI，「对话」与「轨迹」旁会出现**多仓库日志**页签。

> **桌面端：** 插件不会像浏览器那样热更新。安装或升级后请重启 DSH。

## 使用

1. 打开**多仓库日志**页签。
2. 插件会扫描当前会话的工作目录，找出其中的所有仓库（`node_modules`、`bin`、`obj`、`dist`、`target` 等依赖/构建目录与点开头的隐藏目录会跳过）。
3. 点击**拉取**获取远程最新内容，或点击**刷新**重新扫描本地已有内容。
4. 点击任意提交展开详情；点击其中的文件，在右侧查看该文件的差异。

## 需要知道的几点

- **要看新提交，得先拉取。** `git log` 只读取磁盘上已有的内容。别人推送的提交要在拉取之后才会出现 —— 插件不会自行把你的分支拉取或合并。
- **拉取前会先确认。** 拉取会对它找到的每个仓库执行 `git fetch`，所以点击后会先弹出确认。
- **它只负责查看。** 除了拉取，插件只做读取，不会提交、推送、合并或改动工作区。
- **列表是采样。** 每个仓库只取最近的提交（默认 40 条），更早的历史不会显示。
- **它看的是当前会话的目录。** 切换会话（或工作区）即可查看另一组仓库。

## 隐私与安全

- **插件自身不读取、不存储你的凭据。** git 以子进程运行，沿用你现有的 credential helper、SSH 配置与远程设置 —— 和在终端里执行一样；只读请求使用最小环境变量，不会把凭据类变量交给 git；拉取只传递 git 需要的凭据变量，不传递宿主进程里无关的密钥。
- **打开视图不会执行仓库配置的程序。** 只读路由会先中和仓库的 filter/diff 驱动，再交给 git；只有「拉取」才可能执行仓库里配置的程序。
- **只有点击「拉取」才会发起网络请求。** 那是针对你配置的远程执行 `git fetch`；其余请求只发往 DSH 自身的同源 API。没有遥测、没有统计、没有第三方请求。
- **请求由 DSH 鉴权**，且仅作用于已注册工作区内的目录。
- **除拉取外不会改动你的工作区** —— 插件不会提交、推送或合并。拉取只更新远程跟踪引用、`FETCH_HEAD` 与对象；`git status` 使用关闭可选锁写入的模式运行，通常不会改写 `.git/index`。
- **git 可能执行仓库中配置的程序。** 这是 git 的标准行为（`core.sshCommand`、`credential.helper`、`remote.*.uploadpack`、`gpg.program`、`diff` 驱动等）。拉取会作用于它找到的每一个仓库，所以请不要把不受信任的仓库放进 DSH 工作区。完整威胁模型与本插件做的加固见 [SECURITY.md](SECURITY.md)。
